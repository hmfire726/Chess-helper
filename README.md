# ♞ 체스 도우미 (Chess Helper)

스마트폰 화면에 보이는 체스판을 **실시간으로 읽어서**, 다음에 둘 좋은 수를 게임 화면 위에 표시해 주는 안드로이드 앱입니다.
체스 엔진(탐색 AI)과 화면 인식을 모두 직접 구현했으며, 외부 라이브러리 없이 순수 Java로 동작합니다.

## 설치 방법

1. 이 저장소의 **Releases → `latest`** 에서 `ChessHelper.apk` 를 휴대폰으로 다운로드합니다.
   (또는 **Actions** 탭 → 가장 최근 빌드 → `ChessHelper-apk` 다운로드 후 압축 해제)
2. 휴대폰에서 APK를 열어 설치합니다. "출처를 알 수 없는 앱" 설치 허용이 필요할 수 있습니다.

> `latest` 릴리스는 기본 브랜치(main)에 push될 때 자동으로 갱신됩니다. 다른 브랜치는 Actions 탭의 빌드 결과에서 받을 수 있어요.

## 사용 방법

1. 앱에서 **AI 생각 시간**(0.5/1.5/3초), **추천 개수**(1/3/5개), **내 색**(자동/백/흑)을 정합니다.
2. **다른 앱 위에 표시** 권한을 허용합니다.
3. **화면 감지 시작** → 화면 녹화를 허용합니다. (안드로이드 14 이상에서는 **"전체 화면"** 을 고르세요)
4. 체스 앱을 열고, 떠 있는 패널의 **[판 맞추기]** 를 누릅니다.
   판을 **자동으로 찾아서** 격자를 맞춰 주니, 확인하고 **[저장]** 합니다. (틀리면 점을 끌거나 화살표로 1픽셀씩 조절)
5. 게임 **시작 배치**가 화면에 보일 때 **[학습]** 을 누릅니다. 기물 그림을 기억하는 단계로, 앱·테마마다 한 번만 하면 됩니다.
   ([판 맞추기]를 저장할 때 시작 배치가 보이고 있으면 자동으로 학습합니다)
6. 이제 판이 바뀔 때마다 추천 수가 표시됩니다.
   - **┌ ┘ 모서리 표시** = 움직일 기물, **□ 테두리** = 갈 칸
   - 색: 빨강 1순위 · 주황 2순위 · 파랑 3순위 이하
   - 패널에는 기보(SAN)·점수·이유가 나옵니다. 예: `● Nxe5  +1.30  f3→e5  폰 잡기 · 체크`
   - 아래 줄에는 예상 수순(`Nxe5 Nxe5 d4 …`)과 탐색 깊이가 나옵니다.

### 차례와 내 색

체스는 오목처럼 돌 개수로 차례를 알 수 없어서, **판이 바뀔 때마다 어떤 수가 두어졌는지 역으로 찾아내어** 차례를 따라갑니다.
(캐슬링·앙파상·승진도 모두 알아봅니다. 상대가 빨리 두어서 두 수가 한꺼번에 바뀌어도 찾아냅니다)

- 대국 **시작부터** 켜 두면 차례가 정확합니다.
- 중간부터 켜면 차례를 **추정**합니다 (칩에 `차례: 백?` 처럼 `?` 표시). 틀렸으면 **[차례] 칩**을 눌러 바꾸세요. 다음 수가 두어지면 자동으로 바로잡힙니다.
- **[나] 칩**: `자동`은 지금 차례인 쪽의 추천, `백`/`흑`은 내 차례일 때만 추천하고 상대 차례에는 "기다리는 중"으로 표시합니다.

### 패널의 [설정]

| 항목 | 설명 |
|---|---|
| 내 색 | 자동 / 백 / 흑 |
| 판 방향 | 자동 / 백이 아래 / 흑이 아래 (자동: 시작 배치와 폰·킹 위치로 판단) |
| 추천 개수 | 1 / 3 / 5개 |
| 생각 시간 | 0.5 / 1.5 / 3초 |
| 판 프리셋 | `[저장 1~3]`: 지금 판 위치 + 학습한 기물 그림을 저장 · `[불러오기 1~3]`: 바로 불러오기. 앱이나 테마마다 저장해 두면 [판 맞추기]·[학습]을 다시 할 필요가 없습니다 |
| 표시 크기 | 작게 / 보통 / 크게 — 추천 테두리 굵기와 패널 글자 크기 |
| 색 | 추천 색(기본·네온·파스텔·고대비), 패널 색(다크·라이트·네이비·반투명) — 누를 때마다 다음 색 |

## 동작 원리

```
화면 캡처 ──▶ 판 인식 ──▶ 수 추적 ──▶ 엔진 분석 ──▶ 오버레이 표시
(0.6초마다)   (모양 비교)   (차례 파악)  (알파-베타)    (추천 테두리)
```

### 1. 화면 캡처 — `CaptureService.java`
안드로이드 `MediaProjection` API로 화면을 받아 0.6초마다 읽습니다.
**같은 판이 두 번 연속** 읽혀야 확정해서, 기물이 움직이는 애니메이션 중간 화면은 무시합니다.

### 2. 판 찾기 — `BoardLocator.java`
화면에서 8×8 체크무늬를 자동으로 찾습니다. 후보 정사각형마다 64칸의 모서리 근처 색을 읽어
"밝은 칸끼리·어두운 칸끼리는 비슷하고, 두 무리는 다른가"를 점수로 매깁니다.
작게 줄인 화면에서 넓게 찾은 뒤 원래 크기에서 좁게 다듬습니다 (오차 약 3~5픽셀).

### 3. 기물 인식 — `BoardDetector.java`
체스는 "무슨 기물인지"까지 알아야 하므로 **시작 배치를 한 번 보고 기물 그림을 학습**합니다.
기물 그림은 앱·테마마다 다르지만 같은 앱 안에서는 늘 같기 때문에 이 방법이 잘 맞습니다.

| 단계 | 내용 |
|---|---|
| 칸 바탕색 | 칸 위쪽 가장자리 16점의 중앙값 → 마지막 수 강조색이 칠해져도 영향이 적음 |
| 특징 추출 | 칸 안쪽(10~90%)을 16×16 격자로 나눠 격자마다 3×3점을 봄. **기물 픽셀** = 그 칸 바탕색과도, 판의 밝은 칸·어두운 칸 색과도 다른 픽셀. 그래서 같은 기물은 어느 색 칸 위에서도 같은 모양으로 읽힘 |
| 모양 비교 | 학습한 64칸(기물 32 + 빈칸 32)과 비교. 기물 픽셀마다 상대편 ±1칸 안에서 가장 잘 맞는 픽셀을 찾는 **챔퍼 매칭** → 판 위치가 몇 픽셀 어긋나도 외곽선이 맞춰짐 |
| 2단계 확인 | 가까운 후보 5개는 템플릿을 ±1칸 통째로 밀어서도 비교 |
| 가림 감지 | 칸 색이 자기 색보다 반대 색에 가까운 칸이 많으면 팝업·어두운 막이 덮은 것으로 보고 건너뜀 |
| 확인 | 킹이 하나씩인지, 폰이 첫/끝 줄에 없는지 등 실제 대국에서 가능한 배치인지 검사 |

추천 테두리도 화면 캡처에 같이 찍히므로, 테두리는 **칸 바깥 6% 띠 안에만** 그리고 인식은 칸 안쪽 10~90%만 봅니다.

### 4. 수 추적 — `GameTracker.java`
직전 판에서 합법수 1개(또는 2개)를 두어 새 판이 되는지 찾아서 차례·캐슬링 권리·앙파상 칸을 이어 갑니다.
되돌리기(무르기)로 이전 판이 다시 나오면 그 판으로 돌아가고, 체크당한 쪽은 반드시 그쪽 차례라는 규칙으로 추정 차례도 바로잡습니다.

### 5. 체스 엔진 — `Board.java`, `Search.java`, `Eval.java`

| 기법 | 설명 |
|---|---|
| 수 생성 | 64칸 배열 + 미리 계산한 나이트·킹 이동표와 8방향 광선. 캐슬링·앙파상·승진 포함. **perft**(수 생성 개수 검사)로 표준 검증 위치 5곳에서 정확성 확인 |
| 알파-베타 (PVS) | "내가 두면 → 상대는 최선으로 받고 → …"를 여러 수 앞까지 계산하고, 볼 필요 없는 가지는 잘라 냄 |
| 반복 심화 | 1수, 2수, 3수 … 깊이를 늘리다 제한 시간이 되면 마지막 완성 결과 사용. 깊이마다 패널을 갱신 |
| 치환표 + Zobrist 해시 | 이미 계산한 판을 64비트 번호로 기억 |
| 정지 탐색 | 잡는 수가 끝날 때까지 더 읽어서 "잡히기 직전" 판을 잘못 평가하지 않음 |
| 가지치기 | 널 무브, 늦은 수 축소(LMR), 퓨틸리티, 체크 연장, 메이트 거리 가지치기 |
| 수 순서 | 치환표 수 → 잡기(비싼 기물을 싼 기물로, MVV-LVA) → 킬러 수 → 히스토리 |
| 여러 후보 (MultiPV) | 상위 1/3/5개 수를 각각 정확한 점수로 계산해서 순위대로 표시 |
| 평가 함수 | 기물 값 + 위치 점수표(수식으로 생성) + 기동력 + 폰 구조(겹폰·고립폰·통과한 폰) + 비숍 쌍 + 열린 줄의 룩 + 킹 방패 폰. 중반·종반 점수를 남은 기물 양으로 섞음 |
| 무승부 | 3회 반복, 50수 규칙, 메이트 불가능한 기물 구성, 스테일메이트 |

데스크톱 기준 초당 약 100만 수를 읽고, 1.5초에 깊이 9~11까지 봅니다 (휴대폰에서는 기기에 따라 몇 배 느림).

### 6. 오버레이 표시 — `OverlayController.java`
`TYPE_APPLICATION_OVERLAY` 창을 게임 위에 띄웁니다. 표시 창은 터치를 통과시키므로 게임 조작에 방해가 되지 않습니다
(안드로이드 12부터는 불투명도 0.8 이하인 창만 터치가 통과되므로 표시 창의 불투명도를 0.8로 둡니다).
패널은 제목을 끌어서 옮길 수 있고, 판을 가리고 있으면 경고를 띄웁니다.

## 직접 빌드하기

Android SDK가 설치된 PC에서:

```bash
./gradlew testDebugUnitTest   # 테스트
./gradlew assembleRelease     # APK → app/build/outputs/apk/release/
```

GitHub에 push 하면 GitHub Actions가 자동으로 테스트하고 APK를 만듭니다 (`.github/workflows/build-apk.yml`).

### (선택) 고정 서명 키
서명 키를 따로 지정하지 않으면 디버그 키로 서명되는데, 빌드 환경마다 키가 달라질 수 있어서 새 버전을 설치할 때 기존 앱을 지워야 할 수 있습니다.
고정 키를 쓰려면 저장소 **Settings → Secrets and variables → Actions** 에 다음을 넣으세요.

| 이름 | 값 |
|---|---|
| `SIGNING_KEYSTORE_BASE64` | 키스토어 파일을 base64로 바꾼 문자열 (`base64 -w0 release.jks`) |
| `SIGNING_STORE_PASSWORD` | 키스토어 비밀번호 |
| `SIGNING_KEY_ALIAS` | 키 별칭 |
| `SIGNING_KEY_PASSWORD` | 키 비밀번호 |

키스토어 만들기: `keytool -genkeypair -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias chesshelper`

## 한계

- 세로 화면 기준입니다. 화면을 돌리거나 판 위치·크기가 바뀌면 [판 맞추기]를 다시 해야 합니다 (프리셋을 쓰면 편합니다).
- 기물 그림(테마)을 바꾸면 [학습]을 다시 해야 합니다.
- 판 위에 화살표를 그려 주는 앱 기능, 기물을 들고 있는 중의 화면 등은 잘못 읽을 수 있습니다 (두 번 연속 같게 읽혀야 확정하므로 대부분 걸러짐).
- 중간부터 켜면 캐슬링 권리·앙파상은 판 모양으로만 추정합니다.
